# Mixed text and checklist notes

The editor keeps one ordered list of text and checklist rows. The Text and Checklist buttons insert a new row after the paragraph containing the caret. If a multiline text field has more paragraphs, the following paragraphs remain after the inserted row. The buttons do not convert existing rows. A checklist row has a real checkbox; its checked state is retained when saved and reopened. Blank rows and duplicate text stay in their original positions.

The server's note shape stays `kind`, `title`, `body`, and `items`. An untouched text note keeps its body exactly. An untouched legacy `kind: todo` note keeps its body and item array exactly, including blank items and checked flags. Editing only a legacy checklist row with no body keeps the legacy shape. An explicitly composed task-line document saves as `kind: text`, with ordered rows in `body` and exactly one reserved item `{t: "atomic-notes:task-lines:v1", d: false}`. This discriminator opts into parsing; legacy text that happens to contain Markdown checkboxes remains plain text. The discriminator is content and is sealed with the body by the existing vault. Existing legacy body text is retained when adding mixed content.

In an opted-in body, a checklist row starts with exactly `- [ ] ` or `- [x] ` at the beginning of a physical line. The latter means checked. Two-space continuation lines preserve multiline checklist text. Other lines are text. The serializer escapes literal marker and continuation prefixes with a backslash, including repeated backslashes; the editor removes that encoding escape for display. Legacy bodies are never decoded without the discriminator. Blank and duplicate lines retain their order.

Copy emits rows in display order. Done writes the draft through the existing note save path; Back offers save or discard without changing the original note first. No new wire kind or fields are introduced.

Home renders mixed tasks with checkboxes, preserves surrounding text, and includes these notes under To-dos as well as Notes. Toggle events run in order and read the latest stored note, preventing delayed saves from losing a rapid second tap. Search still reads the existing title/body content. An older client can read the task markers as ordinary body text; if it edits and clears the reserved item, the new client safely treats the result as plain text. This is a format downgrade, not a promise of interactive mixed editing on older releases.
