## Executed evidence

**Verified in controlled tests:** `test/sync_http_repository_test.dart:137–315` contains ten controls. HTTP 502 partial acceptance acknowledges the successful note in Hive while the rejected note stays dirty and the caller retains the 10-energy receipt. Three all-failed responses preserve refund amounts 0/3/10 and their corresponding net costs 10/7/0. A legacy response acknowledges the note while billing stays unknown. A synthetic lost response leaves the saved request; closing/reopening Hive and recreating the repository sends the exact same HTTP JSON, request ID and standard mode, with the recovered historical 5-energy receipt. A refused content pull preserves its cursor and prior upload receipt; the next receive-only pull succeeds without another upload. An empty receive-only request has no POST. A 100-note standard attempt sends exactly one 50-row request, with 50 still dirty. A current HTTP 401 retires the caller result, removes the API session and retains dirty Hive rows and the pending request.

**Verified locally:** the ten cases pass on unchanged production code, Flutter 3.44.8 on Windows with shared cache. Strict `flutter analyze --no-pub --fatal-infos` and the full **448-test suite** pass. `git diff` against the baseline for `lib`, `android`, `pubspec.yaml`, `pubspec.lock` and `.github` is empty. This PR only adds its test and proof record. There is no failed-before run to claim: this is characterization coverage for already-correct behavior, not an additional defect correction.

**Verified in code:** the factory disables automatic sync and external balance refresh (`lib/database/notes_repository.dart:70–76`); receipts are collected before per-row acknowledgements (`:773–790`), saved operations retire only after result processing (`:830`), and pull cursors persist at page completion (`:868–876`). Cubit caller identity is checked after the actual repository/transport await (`lib/state/cloud_notes/cloud_notes_cubit.dart:185–200`). The new fixture rejects unexpected routes, uses no real network and deletes only its resolved, named temporary directory after checking the parent.

**Verification boundary:** response totals and HTTP body shapes are fixture inputs; this suite neither runs the Server routes nor proves Drive/Mongo atomicity, real monetary debits/refunds, device keystore/navigation or two-device convergence. Pull success here uses an empty page, not a full note/conflict/crypto wire matrix. Existing independent Server tests retain their own stronger monetary/disposable-database evidence.
