# Cloud Notes receipt presentation

Cloud Notes uses the repository's caller-owned report rather than estimating a completed operation from the advertised batch price. A readable in-page module shows confirmed charged, refunded and net upload energy across the caller's batches. Incomplete receipts show confirmed subtotals only and an explicit unavailable-total notice. Offline/not-started is distinct from a started receive-only attempt; only the latter with no submitted upload has confirmed zero upload charge. Recovered pending requests keep their original receipt amounts and are labelled as earlier uploads whose totals may already have been applied.

The report stays in this page's memory, is cleared when another action starts, and is removed on a source notification with a changed lifecycle/transport-session identity. The cubit captures identity before upload-all marking, checks it before syncing and after awaiting the report, and suppresses joined/retired/closed-page results. It does not continue a stale action by requesting sync in a new session. Repository identity uses lifecycle and API session revisions, without user IDs, tokens or new persistent fields. Existing NotesSource implementations without the report capability keep their existing boolean completion path.

Financial amounts are shown in a wrapping page module instead of the existing three-line snackbar, which can truncate long financial explanations. Count labels also wrap at large text sizes: the initial 375px/2x text fixture exposed a 68px overflow in the existing count-label Row. The receipt module contains no note text or request IDs. Completed/incomplete status and the captured operation error appear separately from cost, so failed pulls do not hide confirmed preceding upload receipts. Unexpected action exceptions release the working state and give a static message without inventing a cost or showing exception values.

Proof scaffold b8e7e8b retains the unchanged UI and adds only the capability boundary plus executable contract fixtures. Its initial run has 13 failing new contract cases and one passing legacy control; this is a missing-contract demonstration, not 13 independent production bugs. Fixture label matching was subsequently corrected to the established uppercase MonoLabel convention. Final cases also cover both actual buttons, exceptional actions and late page closure. All existing repository, transport, lifecycle, counts, pricing and page tests remain required alongside full strict CI and its non-production verification APK.

Boundaries: UI tests use controlled reports, not production wallet/Drive/native behavior. Existing transport tests already verify partial/full/cap-limited receipts on the Server's recoverable 502 note_sync_failed response, which pushNotes accepts before parsing the typed reply. Other HTTP failures, lost responses and malformed/omitted receipts stay unknown. This stage leaves that existing error-response handling, HTTP/wire formats, prices, allowance windows, replay/charging/refund rules, vault behavior, storage and deployment unchanged. The in-memory identity guard cannot cancel a Hive write already executing inside upload-all; storage/account safety remains the repository's responsibility. Native account-switch/navigation, signed upgrades and full-stack acceptance still need verification. Any remaining R8 closure decision must distinguish implemented behavior from those release gates.

Rollback removes the page report field/module and capability use in the cubit, retaining the typed transport and per-call repository collector. No production migration, database/index action, device action or new dependency is involved.
