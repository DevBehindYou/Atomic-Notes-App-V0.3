# USB device acceptance target

This is an alternate test-only entrypoint, not the production login flow. The owner authorized installing/replacing Atomic Notes on the connected Android device on 21 October 2026, including discarding its old 2.03.5 installation. Use fresh test app data; never seed a personal session or point this target at a real account deployment.

`tool/device_acceptance/main.dart` requires the explicit `ATOMIC_DEVICE_ACCEPTANCE=true` define, non-release mode and exact `http://127.0.0.1:24139/api` endpoint. Before writing anything, it checks the guarded Server fixture descriptor for a generated `atomic_test_<20 hex>` database and synthetic owner. It seeds the existing fixture's public synthetic session once, then calls the unchanged production main. Later launches preserve actual cached session/offline/logout behavior rather than reseeding. The production entrypoint never imports this target. Google OAuth and real Google Drive are outside this fixture.

The debug/profile manifests identify the app as Atomic Test and permit cleartext only to 127.0.0.1. Release network behavior is unchanged. The two CI build modes run in parallel and produce one-day APK artifacts with versionCode 2010. Independently verify CI/review and inspect APK identity before installing. USB reverse only device port24139 to the owned loopback fixture's current host port; never expose MongoDB or the fixture on the LAN. The fixture uses actual accepted Server note/auth routes, a generated owned database and simulated Drive.

For measurements, install the profile artifact. `ext.atomicAcceptance.frames` is a profile/debug VM-service extension with an optional `reset=true` parameter. It holds at most1200 timing records in an O(1) queue and returns aggregate build/raster/total frame percentiles. Its16667us count is a60Hz reference, not a device refresh-rate pass. Record actual refresh rate, device/OS, build head, scenario, warm-up, sample count, thermal/charging state and memory separately. Debug results are functional diagnostics, not release-performance evidence. Never publish VM-service authentication URLs or personal app logs.

The acceptance sequence in ACCEPTANCE.md remains authoritative. A fixture pass establishes synthetic native/local-Server behavior, not real OAuth/Drive, production scaling, iOS, browser readiness or a deployment green flag. Stop only owned processes and clean only the exact generated databases and workspace test artifacts after testing; keep the test app available for the owner's manual review unless asked otherwise.
